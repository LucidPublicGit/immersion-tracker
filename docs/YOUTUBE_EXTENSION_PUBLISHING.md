# YouTube extension: permanent Firefox installation

Research checked October 26, 2026. Recommendation: use **Mozilla signing with
unlisted distribution** for personal installation. A public store listing is
optional. A signed XPI installs normally and persists across Firefox restarts;
renaming an unsigned ZIP to `.xpi` does not sign it.
[Mozilla signing overview](https://extensionworkshop.com/documentation/publish/signing-and-distribution-overview/).

## Submission candidate

From the repository root:

```powershell
.\scripts\pack-extension.ps1 -FirefoxRelease
```

Output: `dist/immersion-tracker-youtube-firefox-unsigned.zip` and `.xpi`.
These are **unsigned submission candidates**, not signed releases. The packer:

- Includes the previously omitted `account-select.js` background dependency.
- Uses an explicit file list, excluding local server overrides and secrets.
- Preserves icon paths inside the archive.
- Generates a Firefox-only manifest without Chromium's service worker field.
- Requires Firefox desktop 140+ for built-in data consent, leaving the development
  manifest unchanged.
- Declares required browsing activity, website activity, website content, personal
  identifiers, and authentication information. This maps to transmitted video
  URLs, watch progress, titles/channel metadata, viewer channel IDs/handles, and
  the configured webhook secret. These are code-based classifications and should
  be checked against the final release's behavior before submission.

New AMO submissions since November 3, 2025 require data collection declarations.
Sending data to a self-hosted tracker still counts as transmission; declaring
`none` would be inaccurate. Firefox desktop's built-in consent starts at 140;
supporting older versions requires a separate consent implementation.
[Mozilla built-in data consent and taxonomy](https://extensionworkshop.com/documentation/develop/firefox-builtin-data-consent/).

## Complete the first signing submission

1. Sign in to [AMO Developer Hub](https://addons.mozilla.org/developers/addon/submit/)
   with the account that should own this add-on. Firefox registration has no fee;
   Mozilla requires account two-factor authentication.
   [Mozilla publishing comparison](https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/Build_a_cross_browser_extension#extension_publishing).
2. Choose **On your own** (unlisted) and upload the Firefox unsigned ZIP.
3. Resolve validation/review issues and supply testing instructions. Explain that
   this is a companion to a separately configured Immersion Tracker server.
   Provide reproducible setup instructions or a dedicated test environment if
   reviewers need server access; never submit the production webhook secret.
4. Supply source and build instructions if requested. The current JS is readable,
   but the release manifest is generated by the packer: explain this step and
   include the script/source when requested. Bundled/minified releases require
   reproducible original source.
   [Source requirements](https://extensionworkshop.com/documentation/publish/source-code-submission/).
5. Download Mozilla's **signed XPI** from the submitted version's page after
   signing completes. Signing is not a guarantee against subsequent review.
   [Submission workflow](https://extensionworkshop.com/documentation/publish/submitting-an-add-on/).
6. Record the current tracker URL, secret, and filters before replacing the
   temporary install. Remove the temporary add-on, then use Firefox
   `about:addons` → gear → **Install Add-on From File…** and select the **signed**
   XPI. Keep ID `immersion-tracker-youtube@local.dev` stable. Verify settings,
   **Test server**, live logging, and persistence after a full Firefox restart.
   Do not assume temporary-install storage will migrate automatically.
   [Installing self-distributed extensions](https://extensionworkshop.com/documentation/publish/self-distribution/).

No submission, account registration, signing, or publication was performed during
this preparation. Account access and a Mozilla signing result are still needed.

## Release checks completed

The 1.10.4 submission candidate passes Mozilla `web-ext` validation with
**0 errors, 0 notices, and 0 warnings**. The previous warnings were addressed:

- Android minimum is declared as 142 for built-in data consent; desktop remains
  140. Functional testing here targets desktop, not Android.
- Scan metadata uses plain text, including restored cached results. Old HTML scan
  caches are discarded using a cache revision bump.
- The legacy import redirect runs from a packaged JavaScript file.
- Remote tracker requests require HTTPS, refuse embedded URL credentials, and
  reject redirects. HTTP remains available for loopback only. Existing remote
  HTTP settings must be changed to the server's HTTPS URL.
- The Firefox release disables private-window execution and omits remote HTTP
  optional permissions.
- A packaged privacy page is linked from Settings. Reviewer setup and build
  instructions are in [YOUTUBE_EXTENSION_REVIEW.md](YOUTUBE_EXTENSION_REVIEW.md).

Three Node regression tests verify the request security boundary and safe cache
rendering. Archive checks verify background dependencies, icon paths, and the
exclusion of local overrides/secrets. Mozilla signing and a signed-install test
remain pending account sign-in; lint success does not guarantee AMO acceptance.

[Mozilla Add-on Policies](https://extensionworkshop.com/documentation/publish/add-on-policies/)
require encrypted remote transmission. The page announces a policy revision
effective December 1, 2026; recheck the effective rules for later submissions.

## Updates after installation

For the simplest first installation, install each newer **signed** XPI manually.
Keep the add-on ID unchanged and increment `version` for each release.

To get automatic updates, either publish a **listed AMO release** and let Mozilla
host updates, or keep it unlisted and host an HTTPS update manifest and signed
XPIs. The latter requires a stable `browser_specific_settings.gecko.update_url`
in the release manifest and ongoing hosting. No update URL is configured by the
packer because no durable update host has been chosen.
[Mozilla self-distribution](https://extensionworkshop.com/documentation/publish/self-distribution/),
[updating extensions](https://extensionworkshop.com/documentation/manage/updating-your-extension/).

For other browsers, a Firefox signature does not replace Chrome/Edge store
distribution. This preparation addresses Firefox's temporary-add-on problem.
